# terraform-provider-weka

Terraform provider for configuring a running Weka cluster through its REST API.

Public source: <https://github.com/AbSciBio/terraform-provider-weka>. Keep cluster-specific names, credentials, and endpoints out of this repo.

## Scope

A Weka Kubernetes operator owns the cluster: backends, clients, drives, CSI, and whether protocol services exist.

This provider owns configuration inside a cluster that is already up:

- filesystems and filesystem groups
- quotas and snapshot policies
- object-store buckets
- S3 buckets and policies
- NFS permissions and SMB shares
- organizations, users, and login policy

## Layout

- `internal/wekaapi/` — Go client generated from a pinned Weka 4.4 OpenAPI spec, plus a wrapper for login and calls that finish in the background.
- `internal/provider/` — hand-written resources on top of that client.
- `docs/` — generated by `go generate ./...`.

Contributor conventions are in [AGENTS.md](AGENTS.md).

The provider address is `registry.terraform.io/abscibio/weka`.

## Using an unpublished build

Build the binary and point Terraform at it with [`dev_overrides`](https://developer.hashicorp.com/terraform/cli/config/config-file#development-overrides-for-provider-developers),
so `terraform init` is not needed and no Terraform Registry entry has to exist yet:

```shell
go build -o ~/go/bin/terraform-provider-weka .
```

```hcl
# ~/.terraformrc
provider_installation {
  dev_overrides {
    "registry.terraform.io/abscibio/weka" = "/Users/you/go/bin"
  }
  direct {}
}
```

Terraform warns on every plan/apply while an override is active. That is expected.

## Publishing

`registry.terraform.io` indexes the public GitHub repository. The namespace is the GitHub org, lowercased.

- [x] Public GitHub repository `AbSciBio/terraform-provider-weka`.
- [x] `.goreleaser.yml` and `terraform-registry-manifest.json` (protocol `6.0`).
- [ ] GPG signing key, RSA or DSA. Register the public key on the `abscibio` namespace. Store the private key as GitHub Actions secrets `GPG_PRIVATE_KEY` and `PASSPHRASE`. The release workflow does not run until those exist.
- [ ] `abscibio` namespace claimed: sign in to the registry with a GitHub account that admins `AbSciBio`, then Publish → Provider.
- [ ] Finalized GitHub release tagged `vX.Y.Z`. The tag must not also be a branch name. Pushing the tag runs the release workflow, which uploads the per-OS zips, the manifest, `SHA256SUMS`, and a GPG signature of the checksums.
